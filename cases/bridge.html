Мост Max ↔ Telegram

Асинхронный сервис-шлюз на Python для надежной двусторонней пересылки сообщений, фото и голосовых между закрытым мессенджером Max и чатами Telegram.

Python 3.10+ asyncio PyMax 2.4.1 Telegram Bot API Socket Protocol Privacy & No Telemetry SQLite Session

1. Проблема и технический вызов

Мессенджер Max не предоставляет открытого официального Bot API для внешней интеграции с корпоративными системами и сторонними чатами. Командам, использующим Telegram для оперативной коммуникации и поддержки, приходилось вручную дублировать сообщения или постоянно держать открытыми два разных приложения.

Задача: создать стабильный бекенд-мост, работающий напрямую с протоколом Max, маршрутизирующий переписку строго по заданным парам комнат и обеспечивающий возможность отвечать в Telegram так, чтобы ответ бесшовно возвращался в исходный тред Max.

2. Архитектура и схема потока данных

Источник Чат в мессенджере Max
⇄
Асинхронный шлюз Python-мост (PyMax + Bot API)
⇄
Приемник Парный чат в Telegram

Ответ оператора из Telegram автоматически возвращается в тот же исходный чат Max по ID сообщения.

3. Ключевые инженерные решения

Протокольный клиент PyMax 2.4.1

  • Взаимодействие с серверами Max реализовано через сокетный клиент на основе реверс-инжиниринговой сборки maxapi-python==2.4.1.
  • Клиент эмулирует работу нативного мобильного приложения, обрабатывая сетевые события в асинхронном цикле asyncio.

Изоляция парных чатов (CHAT_MAP)

В конфигурации задаются строгие пары вида ID_чата_Max : ID_чата_Telegram. Сообщение никогда не уходит веерно во все каналы — роутер направляет его строго в привязанный чат. При ответе в Telegram парсер считывает контекст треда и отправляет ответ в исходную комнату Max.

Поддержка медиа (фотографии и аудиосообщения)

Помимо текстовых сообщений с именами отправителей, мост перехватывает прямые временные URI медиафайлов. Если пользователь отправил скриншот или голосовую заметку, сервис скачивает файл в оперативную память и отправляет его в Telegram через соответствующие методы Bot API (send_photo, send_voice).

Приватность и принудительное отключение телеметрии

По умолчанию библиотека PyMax отправляет на серверы мессенджера внутренние события телеметрии с идентификаторами чатов и действиями пользователя. Чтобы гарантировать полную конфиденциальность и отсутствие утечек служебных данных, клиент инициализирован с жесткой блокировкой трекинга:

# Принудительное отключение фоновой телеметрии библиотеки client = Client( phone=MAX_PHONE, extra_config=ExtraConfig(telemetry=False) )

Персистентность сессии без повторной авторизации

При первом запуске скрипта SMS-код вводится единожды в терминале. Криптографический токен сессии и ключи сохраняются в локальную базу данных cache/session.db (SQLite), благодаря чему демон можно перезапускать без прерывания рабочих процессов.

4. Итоги и эксплуатация

Сервис работает автономно в фоновом режиме Linux (systemd daemon), потребляет менее 30 МБ оперативной памяти и обеспечивает задержку доставки сообщений между мессенджерами менее 1 секунды.
